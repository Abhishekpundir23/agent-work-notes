# Work Notes

Two independent local skills for retaining useful agent work records:

- **Codex Work Notes** keeps Codex task notes, a concise continuation brief, and a human-readable work map.
- **Claude Work Notes** provides the same workflow independently for Claude Code.

Either skill folder works alone. They have separate state and host adapters; they do not require collaboration, synchronization, or installation of the other skill.

The record distinguishes decisions, attempts, checks, corrections, evidence, and missing coverage. The brief and map come from one event revision. A fixed byte budget covers the complete brief; overflow directs the agent to exact records instead of silently dropping requirements. The map records stated reasons and evidence, not private internal reasoning.

Requires **Python 3.10+**, using its standard library. The scripts require no model API, embedding service, network access, or package installation. Using the skill still consumes the host agent's normal context and tool budget. Token savings and improved task outcomes have not been established by a comparative benchmark.

## Try it locally

From this repository, choose one script and an existing project directory:

```sh
NOTES="$PWD/skills/codex-work-notes/scripts/notes.py"
PROJECT=/absolute/path/to/your/project
TASK=retry-timeouts

python3 "$NOTES" --root "$PROJECT" --task "$TASK" init --objective 'Fix retry timeouts'
python3 "$NOTES" --root "$PROJECT" --task "$TASK" add --kind constraint --actor user --text 'Preserve the public API' --source 'User request'
python3 "$NOTES" --root "$PROJECT" --task "$TASK" add --kind check --status running --text 'Targeted regression is still running'
python3 "$NOTES" --root "$PROJECT" --task "$TASK" brief --max-bytes 6000
python3 "$NOTES" --root "$PROJECT" --task "$TASK" render --max-bytes 6000
```

For Claude Code, set `NOTES` to `skills/claude-work-notes/scripts/notes.py`. Replace example statements with what actually happened. Explicit `--root` and `--task` prevent a convenient current directory from silently selecting another task's state.

Use a short objective and record restrictions as separate constraints, avoiding duplicate text. Use `batch --file events.json` for meaningful checkpoints rather than recording every unchanged observation. When a brief overflows, use `pending --offset 0 --limit 20`, follow pagination, and `get ID [ID ...]` to recover up to 100 applicable omitted records in one call before acting. If a task ID is unknown, `python3 "$NOTES" --root "$PROJECT" tasks` inventories IDs without selecting one. Each skill's CLI reference covers evidence, corrections, and dependencies:

- [Codex CLI reference](skills/codex-work-notes/references/cli.md)
- [Claude Code CLI reference](skills/claude-work-notes/references/cli.md)

## Install one skill

Copy the complete chosen folder, including `scripts/` and `references/`, into a supported skill directory. Do not overwrite an existing installation without inspecting it.

| Host | Personal installation | Project installation | Explicit invocation |
| --- | --- | --- | --- |
| Codex | `~/.agents/skills/codex-work-notes/` | `.agents/skills/codex-work-notes/` | `$codex-work-notes` |
| Claude Code | `~/.claude/skills/claude-work-notes/` | `.claude/skills/claude-work-notes/` | `/claude-work-notes` |

These layouts follow the current [Codex skill documentation](https://learn.chatgpt.com/docs/build-skills) and [Claude Code skill documentation](https://code.claude.com/docs/en/skills). Reload skill discovery or restart the host if the new folder is not listed. Copying a skill does not configure automatic recording.

## Optional hook capture

```sh
python3 "$NOTES" --root "$PROJECT" --task "$TASK" hook-config
```

This prints configuration. Review it and merge its event groups into `.codex/hooks.json` for Codex or `.claude/settings.json` for Claude Code, retaining existing configuration. Generated commands bind an explicit task: select the intended task before enabling capture. Codex also requires trust review for non-managed hooks.

See the separate [Codex capture guide](skills/codex-work-notes/references/capture.md) or [Claude Code capture guide](skills/claude-work-notes/references/capture.md). Their coverage differs. A settings file is not proof that hooks ran; observe capture in a native host trial before claiming the installation is verified.

## State and evidence

Local state lives under `.work-notes/<host>/events.sqlite3`. Task views live under `.work-notes/<host>/views/<task>/r<revision>-b<max-bytes>/`, with a `current.json` pointer. The owned state directory has a local ignore file so ordinary Git staging excludes it. Review notes before explicitly exporting or sharing them. Rendering refuses to overwrite modified generated bytes; preserve and move the affected revision directory aside before regenerating.

Corrections preserve earlier records. Changes to a premise mark dependent guidance stale, and unresolved competing corrections stay visible. A model or tool record cannot supersede a user constraint, objective, or decision. Caller-supplied actor labels are not authenticated identities. A file hash establishes matching bytes, not correct work or authorship; a record marked passed is only as reliable as its evidence.

`doctor` checks store and evidence conditions. It cannot prove complete capture, correct interpretation, or successful task completion. Hook gaps and absent evidence remain explicit.

## Development and research

See [the specification](docs/SPEC.md), [implementation plan](docs/IMPLEMENTATION.md), and [research findings](docs/RESEARCH.md). Regression fixtures, manual skill-use exercises, and native host/provider trials are different levels of validation. The measured manual trials used 1,000-byte briefs and needed overflow retrieval. Batched `get` supports retrieving those exact records together; this is a usability improvement, not evidence of an efficiency victory.

See [validation results and limitations](docs/VALIDATION.md), the [synthetic example brief](examples/retry-brief.md), and the [human work map](examples/retry-map.md). The example describes supplied fixtures, not actual work on a retry implementation.

```sh
python3 tools/build.py --check
python3 -m unittest discover -s tests -v
python3 tools/build.py --zip
```

Edit canonical scripts in `src/`, then run `python3 tools/build.py` to refresh both independent packages. Archives appear in `dist/`. Optional local timing: `python3 tools/benchmark.py --events 5000 --runs 3`.
